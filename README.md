# RetailPulse

[![CI](https://github.com/Ruze11er/RetailPulse/actions/workflows/ci.yml/badge.svg)](https://github.com/Ruze11er/RetailPulse/actions/workflows/ci.yml)

**Live demo:** [retpulse.streamlit.app](https://retpulse.streamlit.app/). Click **Use sample data** to explore without uploading anything.

**Sales & inventory analytics for small retailers.** Upload a sales spreadsheet
and see what sells, what makes money, what stock isn't moving, and what to do
about it.

Built with Python, DuckDB (SQL), and Streamlit.

> **Status:** MVP complete and deployed on Streamlit Community Cloud. Every number is tested
> against hand-calculated answers, and the suite runs on Python 3.12 and 3.14.

## What you get

| Page | Answers |
|---|---|
| **Overview** | Net revenue, profit, margin, orders, AOV and units, with change vs the previous period; revenue trend by day/week/month; revenue by category |
| **Products** | ABC classes (which products make 80% of revenue), top sellers by revenue, units or profit, and the full product table |
| **Inventory** | Stock value, slow-moving and dead stock, low cover and out-of-stock products, days of stock left per product |
| **Recommendations** | Explainable suggestions: selling below cost, reorder risk, clearance candidates, low-margin best sellers, missing cost data |
| **Data quality** | Accepted vs rejected rows with reasons (downloadable), warnings, and which analyses your data supports |

Every table can be downloaded as CSV. The date range and rule thresholds are adjustable in the sidebar.

## Why it's trustworthy

- **Every metric has a written definition** ([docs/metrics.md](docs/metrics.md)), implemented once in SQL.
- **A hand-calculated golden dataset** ([tests/fixtures/golden](tests/fixtures/golden)) checks every number.
- **Strict input validation** ([docs/data_dictionary.md](docs/data_dictionary.md)). Bad rows are rejected with reasons and never silently "fixed"; ambiguous dates are never guessed.
- **Your data isn't stored.** Files are processed in memory for your session only.

## Run locally

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate    macOS/Linux: source .venv/bin/activate
pip install -r requirements-dev.txt
streamlit run streamlit_app.py
```

Click **Use sample data** in the sidebar to try it without your own files. It loads a year of
sales for a **fictional** coffee & kitchen shop, with planted problems for each page to find
(see [data/sample/README.md](data/sample/README.md)). The data is generated by
`scripts/generate_sample_data.py`.

## Test

```bash
pytest -q          # unit, golden-dataset and app smoke tests
ruff check .       # lint
```

## Project layout

```
streamlit_app.py          UI entry point: page config, navigation, shared sidebar
app_pages/                one file per page (Overview, Products, Inventory, ...)
ui/                       UI helpers: session state & sidebar, charts, formatting, tables
retailpulse/
  schema.py               input contract: columns, aliases, limits, reason codes
  ingest.py               CSV bytes -> all-text table
  validate.py             row rules, warnings, cross-file checks
  db.py                   DuckDB connection + shared parsing macros
  metrics.py              analytics API (KPIs, trends, SKU/ABC, inventory)
  recommend.py            rule-based, explainable recommendations
  config.py               analytics thresholds
  sql/staging/            typing + rejection rules in SQL
  sql/marts/              metric definitions in SQL
scripts/                  seeded demo-data generator
data/sample/              generated demo data (never hand-edited)
docs/                     metrics, data dictionary, decision log
tests/                    pytest suite + hand-calculated golden dataset
```
